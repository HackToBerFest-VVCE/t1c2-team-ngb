# Methodology

## Severity and priority

Official severity and CVSS values are displayed exactly as available from NVD/the configured table. ThreatLens priority is a separate 0–100 heuristic:

`100 × (0.8 × CVSS/10 + 0.2 × max(0, 1 - age_days/365))`

Publication age is computed in UTC from `PUBLISHED`. The recency term reaches zero at 365 days. When CVSS is absent, the available recency component is rescaled to its 20-point contribution; when publication date is absent, CVSS contributes its full normalized 80-point weight. If both are missing, priority is unavailable. This is only an investigation ordering aid; it is not CVSS, an exploit prediction, or proof of active attack.

The CVSS Analysis page ranks directly by the source-provided CVSS Base Score and does not apply ThreatLens priority or recency adjustments. Records with no source score remain unscored and appear after scored records. CVSS is a severity measure, not organization-specific risk; follow the linked NVD record to verify its CVSS version and vector.

Missing or `UNKNOWN` source severity is never silently replaced. If a source CVSS score exists, the Explorer shows a separately labeled CVSS-indicated band using the standard score ranges (0: None, 0.1–3.9: Low, 4.0–6.9: Medium, 7.0–8.9: High, 9.0–10.0: Critical). This hint helps prioritize review but does not assert that the source supplied that severity. Unknown severity with CVSS ≥ 7 is highlighted. Records without CVSS remain unscored and are placed in a manual-review queue; source-versus-score disagreements are flagged for verification. `NONE` is retained as its own source category and is not treated as missing.

Review priority is a rule label, not a probability: unknown source severity with CVSS ≥ 9 is `URGENT_REVIEW`; unknown severity with CVSS 7.0–8.9 is `HIGH_REVIEW`; known source/CVSS conflict is `VERIFY_SOURCE`; unknown severity plus missing CVSS is `MANUAL_REVIEW`. Missing CVSS, missing context, or invalid source values remain visible for verification. Text is not used to manufacture an official severity. An unscored or unmodeled record is not considered safe. Follow the source link and check authoritative NVD/vendor material before deciding impact.

## ML

Descriptions are vectorized with TF-IDF (unigrams and bigrams, max 500 features); K-means uses deterministic seed 42 and a cluster count bounded by sample size. Cluster top terms and representative records are exposed. Silhouette is reported only when defined. A most-frequent-cluster baseline is reported descriptively, not as accuracy. Isolation Forest uses the text vector and median-imputed CVSS, 100 trees, seed 42; lower decision values are more unusual. When more than 5,000 described rows are available, a deterministic 5,000-row sample is used for ML to bound CPU/RAM; dashboards and aggregates use the full loaded result set. The minimum dataset for either analysis is four non-empty descriptions. No labels exist, so accuracy/precision/recall are not reported. Text clusters and anomaly scores do not establish maliciousness or exploitation.

K-means assigns every record in the modeled sample to one of its clusters; it is not an outlier-rejection algorithm. Records with missing/empty descriptions and records outside the deterministic sample are not modeled in that run, and are reported as not analyzed rather than assigned a fabricated cluster. Coverage reports total active records, nonempty-description eligibility, sample membership, actual cluster assignment, actual Isolation Forest scoring, missing-description exclusions, out-of-sample eligible rows, and not-analyzed totals. The percentage denominator is all active non-rejected records loaded from the selected provider. Counts partition the data into missing-description rows, eligible rows outside the sample, in-sample rows below the four-record minimum, and modeled rows. In-sample rows below the minimum overlap the sample-membership count but are explicitly identified as not analyzed.

Modeled rows have deterministic record IDs derived from source fields and an occurrence ordinal for duplicates within the loaded snapshot. Cluster representative records and the paginated ML manifest carry these IDs. Isolation Forest decision values are exposed for modeled rows; a lower value means more unusual, not a numeric exploit probability. The review table labels each CVE `ANALYZED`, `NOT_ANALYZED_MISSING_DESCRIPTION`, `NOT_ANALYZED_OUTSIDE_SAMPLE`, or `NOT_ANALYZED_BELOW_MINIMUM`. An unusual point can still belong to a K-means cluster, and cluster membership does not certify safety or severity.

The configured source schema supplies product summaries but not reliable affected-version ranges or matched vendor advisory records. Those fields are therefore marked unavailable/not queried and require manual verification. `app.services.evidence` defines an optional adapter contract for deployments that integrate authoritative NVD/vendor advisories; the default performs no network requests. An unavailable lookup is not a clean bill of health. All features are decision support only and do not prove exploitation, safety, or malicious activity.

Optional Hugging Face models are trained separately from `hitoshura25/cvefixes`, `vinitvek/cybersecurityattacks`, and `pyToshka/network-intrusion-detection`. Tasks are vulnerable-versus-fixed code snippet classification, CVE severity-from-description classification, incident event-type classification, and malicious-versus-benign honeypot classification when enough labels exist. TF-IDF plus logistic regression uses seed 42 and a held-out split; code examples are grouped by CVE to limit train/test leakage. Scores describe performance on the selected dataset only. The honeypot dataset has only 100 rows according to its Hub viewer and may be skipped if labels are insufficient. No model is a production IDS or a substitute for validation, security review, or source verification. Downloaded datasets and model artifacts stay local and outside Git.

Optional generative analysis uses the selected provider's OpenAI-compatible chat-completions API: NVIDIA NIM for Nemotron, Moonshot's API for Kimi, and DeepSeek's API for DeepSeek. Each requires its own provider-issued API key. An explicit user action sends counts, up to 80 prioritized Critical/High CVEs (severity Critical/High or CVSS ≥ 7), plus up to 20 lower-severity comparison examples, and up to five anomaly candidate IDs to the selected provider; credentials stay server-side. When no key is configured, **Analyze locally** creates a deterministic summary from the same active dataset aggregates and ML results without an external model call. Model output is an interpretation, not source evidence, and must not be treated as an exploitation verdict. No provider call is made until the user clicks **Analyze patterns**.

## Scope

Snowflake reads at most `SNOWFLAKE_MAX_ROWS` (default 500,000; maximum 1,000,000), latest publication first. Overview's recent measure is a rolling 30-day UTC window. Trends are bounded by the selected rolling days and include zero-count months so different windows remain visible. Missing publication dates are excluded from time charts; missingness is exposed in Data Explorer. DEMO mode reads the local NVD snapshot, which can be refreshed using the official annual NVD 2.0 feeds.

For NVD source rows, records whose English description begins `Rejected reason:` are omitted from analytical counts and modeling because the CVE was rejected or withdrawn.

The Critical/High example sample is capped to bound provider request size; full-window aggregate counts are sent separately. A CVE inside the selected window can be omitted once the sample cap is reached. The comparison sample is not used to estimate severity prevalence.
